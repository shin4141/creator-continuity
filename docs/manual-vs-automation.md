# Manual Vs Automation

Creator Continuity has two main usage paths: Paste Mode and Fork Mode. Both share the same core idea: success and failure should be passed forward, not rediscovered every session.

## Paste Mode

Paste Mode is for manual chat users working in tools like ChatGPT, Claude, Gemini, or other LLM chats.

You can use Creator Continuity without using GitHub deeply. Start with the [Lite template](../examples/creator-continuity-lite.md), paste it into your AI chat, and ask the AI to help you fill it in. This can be enough when you mainly need a better handoff between conversations.

Paste Mode is useful when you want the next AI to remember the shape of your work: Aspire, audience, voice, best-known state, success patterns, failure patterns, and what must not drift.

## Fork Mode

Fork Mode is for automation and agentic workflows: AI agents, coding agents, content agents, overnight work, repeated creative runs, or semi-automated pipelines.

Fork the repo when you want a stronger handoff layer for repeated agent starts. Before a new agent begins, route it through the continuity record so it knows what it may do, what it must preserve, where it should stop, and which mistakes should not repeat.

Fork Mode is stronger for repeated agent handoffs because the record can live beside project files, examples, prompts, and source material.

## Shared Boundary

In both modes, the creator keeps the Seat.

Creator Continuity does not automate publishing, revenue, scraping, analytics, or identity preservation. It helps preserve creative continuity so the next session can continue from the actual work instead of inventing a plausible replacement.
